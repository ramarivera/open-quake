# Design

Use electron-builder with native GitHub-hosted runners for five operating-system/architecture combinations. T3 Code at e57c093cdd9032355c6251dd7192280b915b7a23 supplies the matrix and download-format reference. Ramiro's executor desktop workflow supplies the build-without-publish, artifact fan-in pattern. pi-goal publish.yml uses npm OIDC, but open-quake has no distributable npm CLI yet, so no registry package or token is introduced.

Bundle workspace TypeScript and JavaScript libraries into Electron main; keep node-hid and koffi external and unpack their native resources from ASAR. Use tag-derived SemVer as packaged metadata without changing internal workspace versions. PR builds use a prerelease version. Build jobs have read-only repository access; only the tag publication job can write releases. Do not expose publishing credentials to PR builds.

Validate version tags, gate publication on checks and all five native package builds, stage a draft release, upload every required installer and a SHA256 manifest, and publish only after complete upload. Prerelease tags remain prereleases and never replace latest stable. Never overwrite an already published release. Failed runs may leave a draft for a safe retry.

Exercise the distributed artifacts: mount the DMG, extract the ZIP, silently install/uninstall the NSIS EXE, install/remove the DEB and launch the AppImage. NSIS does not automatically launch the normal app after installation. Load real packaged native modules and the actual preload/renderer in hidden smoke windows with isolated user data. Never open hardware or run OS actions in this smoke. Existing bundle tests cover production main startup independently. These checks establish packaging and startup, not full platform/hardware parity.

PR and ordinary local macOS builds remain ad-hoc and may require explicit Gatekeeper approval. Tagged macOS releases require Developer ID signing and Apple notarization. Windows and Linux packages remain unsigned, including tag builds; Windows shows an unknown publisher. Linux HID access needs a scoped udev rule. Linux display, shortcut and media support varies by compositor and isn't claimed equivalent to macOS. No paid runner provider, registry publication, auto-updater or initial public version is required for this change.

Ramiro narrowed macOS to Apple Silicon only on 2026-10-25. Intel Mac builds are excluded; Windows and Linux retain both architectures.

FFmpeg remains a documented external prerequisite rather than a bundled executable. Before recording, probe its encoder list with an eight-second deadline and require libmp3lame. A missing, failed or incompatible converter produces a catalogued installation error before permission requests or capture-window creation. Mock capture and live translation do not need the recording converter.

## Approved release policy 2026-10-27

Linux AppImage is the primary automatic update target. The runtime resolves only stable releases in ramarivera/open-quake, verifies the GitHub asset SHA-256 and byte count, and atomically replaces the existing AppImage after confirmation. deb packages use the owned release page for manual installation. Windows remains unsigned with no paid signing service. The updater integration does not change CI; Apple release signing is configured separately below.


## Apple release signing

macOS tag builds require the existing Developer ID Application identity for team TRGDCMBX3J, hardened runtime, explicit Electron/native entitlements and Apple notarization. Ordinary PR/local builds remain ad-hoc; local signing is opt-in. The certificate is confirmed installed on macmini. Authorized setup recovered the existing project decryption identity, verified that the private key matches the unexpired certificate, authenticated with Apple notarization, and provisioned the five GitHub Actions secrets. The hosted runner consumes a password-protected P12 including that private key plus the existing notarization API key, identifier and issuer as release-step-only secrets. The API key is staged in a private temporary file and included in always-run cleanup. Local signing also accepts a complete Apple ID pair or an existing keychain profile; mixed modes fail before builder precedence applies. Credential provisioning happens separately from the build source; no private credential values enter the repository.

Use electron-builder 26.18.0's canonical temporary-keychain import/disposal and @electron/notarize integration, with an always-run cleanup for leftovers. Preflight rejects missing notarization credentials because this builder otherwise skips notarization even with notarize enabled. Its qualifier omits the Developer ID Application prefix; distribution type and forceCodeSigning prevent fallback to development/ad-hoc signing. PRs cannot opt into signing, and tag macOS builds cannot opt out. Windows/Linux preserve their existing policy. Before collecting assets, inspect the app mounted from DMG and extracted from ZIP for strict signatures, authority/team, hardened runtime, secure timestamp, staple and Gatekeeper acceptance. Keep the existing native package smoke. docs/releases.md records credential references, boundaries and nonpublishing validation. On 2026-10-27, the authorized local combined candidate `d51bd19b` produced a Developer ID signed, Apple-notarized and stapled app in both DMG and ZIP. The verifier passed against both distributed copies, including Gatekeeper acceptance. Later hardware/profile fixes are covered separately by their source checks; this artifact does not claim their native acceptance. No hosted signed tag build or public release has run.
